# Niaro web memory and companion research

Research/design delivery, 30 October 2026. This is a bounded proposal for review, not an implemented feature, another specification framework, or approval to change production code. The owner remains the coordinator/Sol; NIAR-243 owns member memory, NIAR-246 the pet/profile, NIAR-254 composer affordances, and NIAR-255 personal output voice. All example people, projects and facts in the concepts are synthetic.

## What the product needs

A member should be able to see what Niaro has remembered, distinguish their own assertions from machine observations, inspect the evidence, correct or erase it, and stop its use. The pet makes that personal space recognizable. In chat it must leave the message and tool result area clear. The visible interface should remain terse; consequential explanations belong at the action that needs them.

## Primary-source findings

These findings were checked against primary product documentation and standards on the research date. Vendor controls vary by plan and rollout; the descriptions below are evidence for useful interaction patterns, not claims that Niaro implements the same data policy.

| Finding | Primary evidence | Consequence for Niaro — design inference |
| --- | --- | --- |
| Memory inspection, correction and deletion are separate user jobs. A summary need not represent every remembered detail. OpenAI also distinguishes suppressing a mention from deleting the source. | [OpenAI: Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-in-chatgpt), current help page. | Use an inspectable record view, not a personality paragraph claimed to be complete. Label actual erasure as Delete. Do not substitute a vague “Don't mention” control for it. |
| Memory sources can reveal which saved information or prior material contributed to personalization, but a source list is not an exhaustive explanation of a model response. | [OpenAI: Memory in ChatGPT — Sources](https://help.openai.com/en/articles/8590148-memory-in-chatgpt). | The row's source link explains where an observation originated. Do not label it “Why Niaro answered” or promise causal completeness. |
| Claude offers topic-level editing/deletion and distinguishes keeping memory paused from resetting it. Its current and legacy experiences have different project behavior. | [Anthropic: chat search and memory](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context), updated this week. | Keep the global Use memory switch separate from Erase all. Do not import a competitor's project isolation assumptions: Niaro's actual scope is person × workspace. |
| AI correction should be easy to perform; global controls should allow people to change monitoring/behavior. These are general HAI guidelines, not a guarantee of a particular layout's usability. | [Microsoft HAX: efficient correction](https://www.microsoft.com/en-us/haxtoolkit/guideline/support-efficient-correction/), [global controls](https://www.microsoft.com/en-us/haxtoolkit/guideline/provide-global-controls/). The [original CHI research](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/) evaluated 18 guidelines with 49 practitioners across 20 products. | Put Correct in the opened observation detail and the row menu. Put Use memory on the page, not behind the pet's emotional state. Corrections must not disappear from view when their origin changes. |
| Automatic movement alongside other content for longer than five seconds needs a pause/stop/hide mechanism unless essential. Pausing only while focus stays on an element is insufficient. | [W3C: WCAG 2.2 SC 2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide). | Add an independent Animate pet control. A reduced-motion preference alone is not the full substitute for that control. Use a still compact conversation pet by default. |
| Interaction-triggered nonessential motion can be disabled under SC 2.3.3; this is AAA, distinct from the Level A rule above. | [W3C: Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html). | Reduced motion suppresses bobbing, tracking, morphs, particles and reactions. Do not simulate calm by retaining a slow infinite animation. No storm flashes are necessary for understanding weather. |
| Reflow should preserve content and function at a width equivalent to 320 CSS px. Focused controls must not be entirely obscured by author-created fixed content. | [W3C: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html). | Keep the pet centered and move surrounding section controls into readable rows; keep one vertical document. Composer/keyboard height must reserve space in the message scroller. Rich tables may scroll within their own region; the entire app should not. |
| WCAG 2.2's AA minimum target size is 24 × 24 CSS px, with exceptions. Larger targets help on touch. | [W3C: Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). | Aim for 44px touch targets, while keeping the glyph visually small. Do not claim 44px is the AA threshold. Source chevrons and ellipses need separate targets. |
| Chat products expose adding local files from the composer; Microsoft distinguishes uploading files from referencing already accessible work entities. | [Anthropic: upload files](https://support.claude.com/en/articles/8241126-upload-files-to-claude), [Microsoft: reference files and more](https://support.microsoft.com/en-us/microsoft-365-copilot/refer-to-specific-files-and-more-in-microsoft-365-copilot). | Keep paperclip visible on the initial chat. Its menu contains Add file and Reference task. Keep @ for the existing mention directory. A task reference is not a file and must not imply execution. Do not copy competitors' file limits. |
| Editable combobox patterns preserve input focus while navigating options, expose the active option, accept deliberately, and close on Escape. | [W3C ARIA APG: Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/). | Preserve Niaro's caret/IME handling and keyboard reference picker. “@” is a discoverable button as well as a typed shortcut, particularly on mobile. |
| Location is a sensitive input requiring deliberate consent and purpose limitation. The Geolocation specification currently is a Candidate Recommendation Draft, not a final Recommendation. Weather APIs take coordinates, so a city name is not by itself the complete transport. | [W3C Geolocation, dated 30 October 2026](https://www.w3.org/TR/2026/CRD-geolocation-20261030/), [Open-Meteo forecast API](https://open-meteo.com/en/docs). | The accepted foreground coarse-phone/manual-city choice needs a separate control, revocation and a clear source. Never infer city from memory or request precise/background location just to animate a pet. User authorization, not the API documentation, establishes this feature's scope. |

No source establishes that a specific mascot size, radial section placement or a “cute” appearance improves productivity. The centered pet and surrounding sections are the latest explicit user direction, not a research-derived productivity claim. The 320px main profile canvas (210px expanded / 220px narrow), 230px new-chat canvas and 42px still conversation canvas are design hypotheses chosen to preserve readable controls and match the actual renderer. They require product review and later real usability testing. No dependency, wellbeing, streak or affection mechanic is proposed.

## Conclusions to carry into the canonical changes

1. Preserve `/me/memory` as the privacy record manager and `/pet` as the personal profile. Reuse the same record/actions components and API, not a second memory store. Corrected observations remain visible under Saved.
2. Stop learning/use separately from deletion. Keep stored rows inspectable and erasable when memory is disabled; suppress unavailable Correct actions instead of hiding the content.
3. Do not ship a complete-looking profile backed by an unmarked 200-item sample. Add authenticated, version-consistent paging to NIAR-243 before claiming full browsing; retain all-lineage erasure independently of visible pages.
4. Work/Personal applies only to observed records. No hidden reclassification of explicit facts, permission implications, or fabricated provenance snippets.
5. Use motion sparingly, with a persistent user control. The small header pet opens the profile and leaves the reading column intact. The same composer remains mounted and in the same place across first send.
6. Center the profile pet with six named memory-section controls, readable expanded detail and normal keyboard order. This latest user direction supersedes the rail candidate; narrow views retain the center and use 44px-or-larger section controls. Use the supplied outline pet-face nav icon without changing brand masters.
7. Weather, appearance, output voice, privacy and confirmed position are distinct controls with distinct effects. The new personal weather choice supersedes NIAR-246's workspace-only/no-phone-location assumption only after canonical amendment.
