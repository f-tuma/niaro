# Centered mobile Pet proposal and composer review

Open [the gallery](gallery.html) or [the interactive prototype](prototype/index.html). The Pet/profile screens use synthetic local records; they are a tested design proposal, not a production profile, weather implementation or aesthetic approval.

[Design](design.md), [fidelity ledger](fidelity-ledger.md), [QA receipt](qa.md), and [composer review](composer-review.md) record the boundaries and evidence. The composer review covers the exact five frozen source pins, four native language/size cases, retained keyboard focus and synthetic reference metadata. The profile prototype has 27 rendered layout cases and keyboard/dialog checks. Existing pet, logo and font assets are reused through repository aliases.

The historical report records a normal-entry connection guard after the host restart. Root subsequently restored the actual App Home against a real paired synthetic HTTP fixture using a preview-only in-memory credential port. Existing device credentials, permissions, APK and data were preserved. This restoration does not prove real-account backend persistence, provider compatibility or real audio.

Production integration must retain actual memory provenance and revision/conflict semantics, resolve the documented complete-browsing limit, and use the accepted shared pet engine. The static prototype does not replace its touch or animation behavior.
