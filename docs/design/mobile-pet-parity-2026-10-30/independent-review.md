## Cadence evidence and limits

The native context reports Android Emulator OpenGL ES Translator backed by NVIDIA RTX5070Ti. An early short idle run delivered29.884fps. After a subsequent isolated Metro reload, the195-second run delivered about20.4 active fps and15 calm/doze fps. To distinguish the limiter from available callbacks, I observed native requestAnimationFrame callbacks *before the unchanged PetView cadence*:20.633 callbacks/s and20.642 draws/s in the same35-second window, predominantly33/67ms callback gaps (`raf-diagnostic-summary.json`, `metrics-raf-diagnostic.json`). The limiter is not dropping the absent active frames in that run. Integer division can underfill a20fps cap on the delivered callback cadence. The nominal30/20/15 values are upper budgets, not a sustained physical-device promise.

Animation time progressed continuously through195 seconds without catch-up bursts, doze thresholds and wake worked, and the high-frequency input regression is independent of render cadence. Shader JS submission p95 in the diagnostic is0.105ms; that excludes GPU completion and endFrameEXP, so it is **not** a GPU timing or phone performance claim. Browser SwiftShader renders establish appearance only.
