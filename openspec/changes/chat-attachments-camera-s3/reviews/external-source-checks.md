# External documentation checks

The review coordinator opened the design's primary research links on 2026-10-30. These are documentation checks, not runtime, compatibility, security, licensing-completeness or performance tests. The isolated reviewers' own limits remain separately recorded in their reports.

- [RustFS Docker setup](https://docs.rustfs.com/en/installation/container/docker) describes persistent named volumes, non-default credentials, a non-root container and separate API/console listeners. Niaro still needs a pinned release and a local contract run.
- [RustFS S3 compatibility matrix](https://github.com/rustfs/rustfs/blob/main/docs/architecture/s3-compatibility-matrix.md) documents supported object operations and range reads, with selected versioning/Object Lock coverage rather than universal S3 compatibility. This supports the design's endpoint-specific evidence requirement, not a claim that its exact SDK configuration already works.
- [Hetzner supported actions](https://docs.hetzner.com/storage/object-storage/supported-actions/) lists deviations including unsupported ownership controls, tagging and GetObjectAttributes. [Endpoint setup](https://docs.hetzner.com/storage/object-storage/getting-started/using-s3-api-tools/) describes location-bound endpoints and project-bound credentials. The design's common operation subset still requires a designated-bucket live run.
- [Docling](https://github.com/docling-project/docling) distinguishes code licensing from individual model licensing. Its [format list](https://github.com/docling-project/docling/blob/main/docs/usage/supported_formats.md) includes the principal Office, PDF, image and structured-text formats, while [installation guidance](https://github.com/docling-project/docling/blob/main/docs/getting_started/installation.md) shows that OCR engine/assets must be deliberately configured. Format support is not evidence of Niaro fixture fidelity or resource fit.
- [MarkItDown](https://github.com/microsoft/markitdown) explicitly warns that parsing operates with process privileges. The linked [OCR plugin](https://github.com/microsoft/markitdown/blob/main/packages/markitdown-ocr/README.md) uses vision-model calls and can continue after OCR errors. A pilot must therefore specify a compliant local OCR path or explicitly route any model step through Niaro and preserve partial/failure evidence; enabling this plugin unchanged would not establish compliance.
- [Apache Tika](https://github.com/apache/tika) and [Unstructured](https://github.com/Unstructured-IO/unstructured) were accessible as alternative project references. No comparative deployment benchmark was performed.
- [Expo SDK 57 ImagePicker](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/) documents original HEIC/AVIF behavior and editing/export options. Native source-byte preservation and normalization still require device evidence.
- [HTML capture](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture) has limited browser availability. [getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) requires a secure context. These support the planned fallback and explicit browser checks; no browser/device capture was exercised by this review.

The [RustFS container index](https://docs.rustfs.com/en/installation/container) was also opened. No service accounts, private endpoints, uploaded customer files or external people were accessed.
