## Goals / Non-Goals

**Goals:** keep timbre choice personal and separate from routing privileges; offer real reviewed options without a synthesis/discovery side effect; preserve strict existing speech clients; validate current authorization, route and allowed voice at the actual paid boundary; show current default/fallback and concurrent-edit failures honestly on mobile and web.

**Non-Goals:** generic new provider support, input/transcription settings, custom/cloned voices, preview audio, browser speech input/playback, pet/weather preference infrastructure, runtime catalogue administration, dependencies, new synthesis retries, spend accounting or a durable audio/request ledger. Fallback-only is safe degradation and is not completion of the personal-choice intent when no alternatives can be admitted for the selected route.

### D2. Separate negotiated personal settings resource

Keep every `agent-speech/1` request, capabilities and result shape unchanged. Do not extend `SpeechCapabilitiesSchema`, `SpeechRequestSchema`, snapshots, ServerInfo, workspace routing schema or message metadata.

Add **GET and POST `/v1/{workspace}/voice/output-settings?profile=agent-output-voice/1`**. The new resource and explicit query profile are the opt-in negotiation. GET authenticates before returning a complete strict snapshot; POST must follow a successful GET in the UI. A new client on an old server treats 404 or profile-specific 406 as **preference unsupported**, continues existing speech capabilities/playback, and does not send POST. Auth/network/parse errors are not reclassified as unsupported or speech disabled. Old clients never request the resource and see identical speech JSON. The new server returns 406 `output_voice_profile_unsupported` for missing/unknown profile on this resource. Existing demo a/b routes return unsupported (no persistent personal preference) unless a test explicitly supplies this capability.

Proposed schemas, in new `packages/protocol/output-voice.ts`, all strict and bounded:

```ts
// UUID requestId; bounded safe integer revisions; 64 lowercase hex digest tokens.
type Choice = { kind: "server-default" } |
  { kind: "catalogue"; optionId: string /* opaque ov_<64hex> */ };
type Snapshot = {
  profile: "agent-output-voice/1";
  scope: Scope;                 // existing authenticated scope, never client supplied
  revision: number;             // personal CAS revision, initial 0
  catalogueRevision: string;    // actor-scoped digest of full current public catalogue binding
  availability: "selectable" | "server-default-only" | "speech-unavailable";
  route: null | { identity: string; model: string; method: "reader" | "speech" };
  serverDefault: null | { label: string }; // e.g. "Cedar", bounded 200 chars
  options: Array<{ optionId: string; label: string }>; // <=32; no default duplication required
  saved: null | { choice: Choice; label: string };    // last saved intent, not current validity
  effective: {
    choice: Choice;
    label: string;              // default label is voice name; UI localizes "Server default"
    reason: "server-default" | "selected" | "saved-choice-unavailable" | "speech-unavailable";
  };
};
type Update = {
  profile: "agent-output-voice/1";
  requestId: string;            // mutation UUID, not a speech request ID
  expectedRevision: number;
  catalogueRevision: string;
  choice: Choice;
};
// Success returns Snapshot with no extra success wrapper.
```

For disabled speech: route/serverDefault null, options empty, effective default choice/empty label/reason speech-unavailable; a user can still clear a stale saved choice to Server default. No raw provider credentials, URLs, client-selectable model/provider, org/actor targets or raw provider voice strings in POST. Labels are plain text, not HTML and not provider marketing descriptions. Only server registry maps optionId to provider voice.

`route.identity` and catalogueRevision are SHA-256 over a canonical versioned serialization including organization/workspace/user identity, provider ID/revision/canonical URL, catalog model ID/revision/upstream model, **speech binding epoch** (see section 5), method, format, ZDR requirement and registry policy revision. catalogueRevision additionally includes the configured default and advertised option mapping. A default-label/value change changes the catalogue token but does not invalidate a still-supported explicit personal choice. The digest is correlation/optimistic concurrency, not authorization or a secret capability. Option IDs are derived from the same scoped route identity plus provider voice and do not authorize anything independently. Never log keys or speech text as catalogue diagnostics.

Statuses: 200 read/save; 400 invalid_payload (unknown fields, raw voice/provider IDs, malformed bounds); 401/403 existing auth; 406 unsupported profile; 409 `output_voice_conflict` for personal revision mismatch or `output_voice_catalogue_changed` for stale route/catalogue; 422 `output_voice_choice_unavailable` for a well-formed nonadvertised option under the current token; 405 method; provider route unavailability is a valid GET snapshot, not a remote probe or whole-page failure. Error body stays `{error: code}`; client refetches a snapshot before offering an explicit retry.

Additional protocol bounds: mutation requestId is UUID; revision/expectedRevision are safe integers in 0..Number.MAX_SAFE_INTEGER; digest tokens are exactly 64 lowercase hex; option IDs match `ov_<64hex>`; option labels are trimmed plain text of 1..100 characters, default label at most200 and model at most200; GET/save response at most32KiB UTF-8 and POST body at most2KiB. Choice objects and every nested object are strict. For an explicitly saved default, saved.label is empty and the client uses its localized Server default label plus current serverDefault.label; a disabled effective voice has empty label. A corrupt/unreadable personal row produces a safe default/fallback view, never an exception that disables unrelated chat.

Alternative considered: append fields to agent-speech/1 or add voice fields to synthesis requests. The first breaks strict clients; the second hands clients unneeded routing input. A separate resource makes negotiation independent and leaves speech envelopes byte-shape compatible. Existing demo a/b workspaces remain unsupported unless a synthetic test explicitly provides this personal capability.

### D3. Actor-scoped persistence, compatibility and conflict semantics

Create one `OutputVoiceStore` in the existing identity SQLite database, via `apps/server-identity/output-voice.ts`. Do not couple this to unaccepted pet/weather settings or workspace AI profiles. Synchronous store operations run only in the existing identity queue; no network I/O in the store.

Additive table `agent_personal_output_voice`: primary key **(organization_id, workspace_id, user_id)**; revision (initial absent=0), choice_json with schema version, saved_label, binding_json (null for default), last_request_id, last_request_digest, last_write_revision and updated_at. Workspace/org/user foreign keys use the existing identity tables with cascade cleanup; also retain the authenticated organization member_id as an internal FK to member(id), resolved server-side from org/user, so organization-membership deletion cascades the preference. For members, enforce current workspace membership from authenticated runtime on every operation; organization admins may update only their own row through this personal API. An admin target in the body is rejected. Workspace membership revocation immediately blocks all operations and revokes existing mobile sessions through the current setWorkspaceMember path; the dormant preference may remain for the same user if access is later restored. Organization member removal deletes the preference through member_id FK, so rejoining that organization starts from Server default. No private value moves to another user in either case.

The saved catalogue compatibility binding includes exact provider/model/method/privacy/registry identity plus a speech-specific epoch, and excludes the configured default so a valid explicit personal voice survives an administrator default-voice change. Add `agent_output_voice_route_epoch` keyed (organization_id,workspace_id), storing canonical last speech binding digest and monotonically increasing epoch. `saveRouting`/model/provider changes affecting that compatibility binding must advance it in the same identity queue; default-voice-only or unrelated chat routing edits must not change it (the catalogue token still changes for a changed server default). This avoids reviving a choice when provider A changes to B and later back to A. Prefer maintaining the epoch lazily on every settings read/save and synthesis pin plus a narrow ServiceCatalogStore hook on relevant catalog commands; **the hook is required to observe an A→B→A change between reads**. Persisted absence reads as epoch 0; initialization creates only current metadata, not settings for every actor. Conservative epoch invalidation on provider/model revision is acceptable and reported honestly.

Save: derive actor on the server and parse exact Update. Under one queue turn, first compare the last committed mutation ID: a matching ID and digest returns the current snapshot without a write or CAS/catalogue rejection, while a matching ID with different content conflicts. Otherwise read current catalogue, reject stale catalogue/personal revision, resolve option ID in that actor's advertised set, then atomically commit choice and revision. `server-default` stores an explicit following-default preference without pinning the voice value. Choice equality compares saved intent, not effective fallback; a same-intent save is a no-op and does not increment revision, while clearing a stale saved catalogue choice to `server-default` is a change even when default is already effective. Keep the last committed mutation ID and a canonical parsed-payload digest; a no-op need not create a committed mutation record. Replay resolves the known prior outcome without reapplying it under changed routing; all new mutations still require the current catalogue token. Older unknown retries fail CAS and refetch; no hidden reapplication over a newer choice. No automatic POST retry after timeout; GET resolves uncertainty and UI asks for a deliberate retry only if needed.

Read/effective resolution is nonmutating for personal preferences: saved valid matching catalogue binding → selected voice; absent/default → current workspace voice; removed voice, changed catalogue/provider/model/method/epoch or corrupt/old saved data → current workspace voice with reason saved-choice-unavailable. Keep stale saved label only to explain fallback and offer Reset/choose again. A changed label alone is not a different voice, but a registry policy revision invalidates stale token/binding conservatively. Disabled speech shows unavailable; no audio dispatch. A later speech re-enable starts from the current route epoch and cannot silently revive a prior custom choice. Sign-out preserves the person's server setting but clears client display/in-flight ownership; account/workspace switching never copies it to another identity.

Store updates and catalogue compatibility changes use the existing single identity queue and atomic SQLite operations. The route epoch hook records every relevant successful catalog command, including an intermediate A→B→A sequence; merely recomputing the current digest on the next read is insufficient. No remote I/O occurs in this store. Default-only edits change the catalogue token, not saved compatibility. The default voice is intentionally not pinned in a following-default preference.

Alternative considered: local device preferences or workspace routing writes. Local-only preferences do not sync mobile/web; workspace writes affect other people and require administrator authority. A separate voice store avoids coupling this bounded feature to unaccepted pet/weather storage.

### D4. Effective voice frozen and revalidated at real dispatch

In `accountRuntimeAccess`, expose personal output-settings callbacks through a settings-only guard in the existing identity queue. It reauthenticates current membership/scope and closing state without the general runtime's captured model-policy check, so the store can enforce the documented current catalogue conflict and last-receipt rules. Keep the general `run`/`check` and synthesis guards unchanged. Derive the actor `{organizationId: orgId, workspaceId, userId: initial.session.scope.userId}`. HTTP trusts neither URL actor overrides nor body scope. Browser uses the same short workspace credential as mobile, so both surfaces share the same persisted preference.

At `synthesizer.synthesize` entry, inside the identity queue, re-resolve the **current** enabled speech route and current catalogue, resolve this actor's effective voice, and freeze an immutable internal `SpeechSelection` plus route/catalogue epoch, model/provider revision and chosen voice. Client speech request still contains no voice. A stale saved preference already invalid at this point uses current server default with the explicit settings fallback reason.

At every real transport `beforeDispatch`, in the same existing guarded identity queue turn: check abort; reauthenticate/check current policy; retain the HTTP guard's current scoped assistant text check; re-resolve current route and compare provider/model ID+revision, method, privacy/default and speech epoch to the pin; revalidate pinned selected voice against the current registry; call existing `useProvider` exactly once for the actual attempted provider request; only then `start()`. If any route/catalogue/authorization/text changed after pin, fail closed before the paid call using existing `speech_context_changed` or existing sanitized speech failure mapping. Do not silently switch provider/voice or start fallback synthesis inside this already-admitted request.

The existing one verbatim retry uses **the same frozen voice pin**, revalidates each actual dispatch and charges the same existing provider limit. A preference saved while synthesis is underway affects the next synthesis only; it does not replace the current pin or add a retry. An underlying voice removed from the allowed registry invalidates the current pin before a subsequent attempt. After provider return retain auth/current-text validation, current route validation, abort and playback generation checks before returning/playing audio. No new fallback call on refusal, timeout or provider error: keep text and existing playback error handling. Current voice change does not itself stop/restart already playing audio.

Idempotency boundary is explicit: workflow commands and their durable journals are untouched; settings use CAS and last-mutation replay semantics; built-in synthesis retry stays pinned; ClientSession does not automatically replay synthesis POST. Existing speech HTTP has no durable requestId ledger and repeated explicit POSTs can synthesize again. This plan does **not** claim durable speech replay or add an audio cache. If the coordinator requires a new never-resynthesize guarantee across repeated explicit HTTP requests/crashes, that is a distinct accepted contract/storage slice (request ledger, bounded replay/unknown policy, tests), not something to imply from requestId or smuggle into personal settings.

The existing speech integration remains the single provider path. No preview or catalogue probe is added to its transport. A provider refusal of a pinned option yields existing sanitized speech failure/text behavior; it is not an opportunity to retry Cedar or another model automatically. The dedicated speech branch's existing missing privacy-policy forwarding is recorded here as a blocker to enabling any new TTS catalogue, not silently repaired or relied upon by the initial reader-only pin.

### D5. Minimal mobile/web editor and playback ownership

ClientSession owner adds `outputVoiceSettings(signal): Promise<Snapshot | null>` (null only negotiated unsupported) and `saveOutputVoiceSettings(Update,signal): Promise<Snapshot>`, via existing private authorized json transport. Validate profile/schema, existing `sameScope` against current credential, bounded response (32 KiB), and request/response ownership. No public transport escape hatch or new provider call. Both methods fail after session stop/identity change. Errors remain distinct enough for conflict, catalogue refresh, save uncertainty and sign-out handling.

Mobile owner adds a small presentation-only `packages/ui-catalog/OutputVoiceCard.tsx` in `apps/mobile/VoiceSettings.tsx`; VoiceSettings owns ClientSession GET/save effects and the existing `DetailSheet`, while the shared card receives display values/callbacks and never imports mobile code. Reuse current ListRow option rows, EN/CS labels in `packages/i18n/index.ts` and accessible selected/loading/error states. Place the card below spoken replies when those controls render, but mount the supported output editor independently of the combined no-input/no-speech early return. An unsupported sidecar may be omitted; a supported speech-unavailable snapshot must still permit Reset of a stale saved catalogue choice. Server-default-only/unavailable states use a current label, concise contextual detail and that Reset when needed, without an inert alternative picker. Selection never changes input transcription or toggles spoken replies. No preview button/call.

When selectable, the mobile sheet offers Server default plus advertised labels. Tapping a different option immediately starts exactly one settings POST; there is no draft selection or extra Save confirmation. Keep the sheet open, disable further choices/Reset and retain the last acknowledged snapshot and selected display while saving. Compare the chosen intent with the acknowledged saved intent (absent/default means following Server default), never only with `effective.choice`: selecting Server default must clear a stale saved catalogue choice even when effective fallback is already default. Selecting the same acknowledged intent is a no-op. A successful same-scope response applies its returned snapshot and closes the sheet. A failed save keeps the sheet open with a concise contextual error and the prior acknowledged selection. A stale-choice Reset uses the same save/acknowledgement lifecycle.

Scrim, back and swipe dismissal remain available while saving. Dismissal cancels client waiting and invalidates completion ownership so an ignored-abort late result cannot update or reopen the sheet; it never claims the server rolled back a possible commit. Reconcile with a passive GET on reopening or returning to settings. No App.tsx/ReplySpeech/composer behavior change is proposed for an output-voice-only save; the playback clarification below remains subject to review.

Web owner adds `apps/server-admin/web/app/output-voice-settings.tsx`, mounted from existing `account-page.tsx`. It reads `useApp().session`, workspace and identity; uses the same new ClientSession methods and actual own setting; uses existing console Section/Field/Select/loading/error primitives and EN/CS copy. The normal Select value-change event starts the single save with no extra Save confirmation; its popup follows the normal Select lifecycle, while the field retains acknowledged state, disables changes while saving and applies only the returned same-scope snapshot on success. Failure shows a concise contextual error with the prior acknowledged selection. When stale saved catalogue intent is already falling back to effective Server default, expose a concise explicit Reset action even though choosing the already displayed Select value may emit no change event; use the same save lifecycle and remove that action once no stale choice remains. Do not add an always-duplicate Reset button or permanent helper prose. The section identifies the spoken-reply voice preference without adding browser recording/playback. No new admin endpoint, browser sign-in or navigation route is needed.

Both clients key displayed/load/save state by session instance + server/connection/workspace/user, abort and clear on identity/workspace change, and use a generation counter to ignore late GET/save completion even if abort is ignored by transport. A GET started before a successful save may not overwrite the newer revision. Conflict or catalogue change invalidates/refetches current state and requires a new explicit selection, with no automatic reapply. An unknown save outcome retains the last acknowledged display with an uncertainty state and first reconciles through passive GET; only a deliberate retry may reuse that pending requestId and exact body, never an automatic POST replay. Saved intent and effective fallback remain distinct in every acknowledged snapshot; no optimistic choice is shown as committed. Refresh on settings entry/return, reopening, foreground and after a conflict; no background poll and no provider catalogue refresh.

**Explicit proposed reconciliation with main voice spec:** its current phrase “changing preferences” predates a personal output-voice setting. The delta narrows that cancellation trigger to the existing spoken-replies on/off preference, preserving all other Stop/navigation/background/session/replacement/timing fences. A save of only output voice applies to the next invocation and does not stop or restart already-playing audio; the server's already-frozen invocation does not adopt the new voice. Review this exception explicitly. If product review instead requires cancelling current playback on output-voice saves, revise the delta, client boundary and task before implementation; do not silently change App/ReplySpeech under the backend ownership gate.

## Risks / Trade-offs

- **Reader per-model evidence gap** → initial Alloy/Echo/Shimmer pin remains a visible acceptance decision; unknown/unreviewed routes default-only; no live or paid validation is claimed. A missing metadata field does not establish unsupported voices, and configured Cedar does not certify other voices.
- **Provider schema/documentation disagreement** → preserve the small upstream-contract intersection and exact route identity; the published OpenRouter SDK/OpenAPI omission is documented; do not install a different transport to hide it.
- **Stale authorization, provider/model or text** → retain existing guard ordering and add current speech pin revalidation before every dispatch and return; no automatic switch/retry.
- **Cross-account or late completion** → server derives the tuple and clients fence responses by session/identity/generation and revision.
- **Concurrent saves or lost responses** → CAS plus last-committed mutation semantics, no optimistic success/no automatic POST replay, current-state refetch.
- **Existing spend/dedupe gaps** → preserve current quota/concurrency and workflow invariants without claiming unimplemented speech guarantees or expanding into a new ledger.
- **Overbroad invalidation** → a provider/model revision conservatively invalidates a saved choice, while a default-only or unrelated routing edit does not. Catalogue metadata remains small and no audio/history is retained.

## Migration Plan

After design acceptance and a separate exact-file implementation gate, deploy the additive server store/resource first. Existing rows and all legacy speech shapes remain readable; absent preferences resolve to the current server voice. Add new clients only after negotiated GET is available; older servers degrade the preference editor without disabling existing speech. No database backfill, provider discovery, paid call, restart action, provider activation or saved-session mutation belongs to this draft task.

Rollback before client rollout can leave the additive tables dormant. Rolled-back clients continue strict legacy speech and the server still applies an existing valid personal preference; rolled-back servers return unsupported on the sidecar resource. Never reinterpret an opaque option as a raw provider voice, migrate it to another provider automatically, or delete a person's setting just to make a read succeed. Provider/model compatibility changes invalidate old pins through the epoch rule. Deployment/publication are separate root-owned actions.
